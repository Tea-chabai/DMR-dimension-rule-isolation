# Dimensional Rule Isolation

**Every dimension gets its own `/gamerule` — vanilla clients welcome.**

Minecraft 26.3 moved game rules to the server: `ServerLevel.getGameRules()` now returns one
global rule set, so `/gamerule keep_inventory true` changes the overworld, the nether and the
end at once. This mod redirects that lookup per dimension. No new syntax, no registry content,
no client mod.

## Features

- **Per-dimension rules** for the overworld, nether, end and **any datapack dimension**.
- **Vanilla `/gamerule` just works** — it reads and writes the executing dimension's rules.
- **Per-dimension difficulty** — mob damage, spawn checks and the client HUD follow the
  dimension's own value; no more one global difficulty for every world.
- **Per-dimension weather** — rain, clear sky and thunderstorms stay inside the dimension that
  changed; weather packets are filtered per dimension.
- **Per-dimension recipes** — claim datapack namespaces per dimension; crafting tables,
  furnaces, stonecutters, smithing tables and brewing stands only see the claimed set.
- **Per-dimension time offset** — time keeps flowing, but each dimension can sit at its own
  time of day; undead burning, villager schedules and sky darkening follow the offset.
- **Named groups** — create a group, add or remove dimensions freely; members share one live
  rule set while everything else stays isolated.
- **Persistent** — rules, groups, difficulties, weather, time offsets and recipe claims live in
  a readable JSON file and survive restarts.
- **Server-side only** — no blocks, items, entities or custom packets. Vanilla clients can join.
- **Cross-dimension death fix** — dying in a `keep_inventory=true` dimension and respawning
  elsewhere no longer deletes your inventory (a vanilla asymmetry that only appears once rules
  differ per dimension).

## Commands

| Command | Permission | Description |
|:--|:--|:--|
| `/dmr list` | 2 | List groups and ungrouped dimensions |
| `/dmr group create <name>` | 3 | Create an empty group |
| `/dmr group add <name> <dimension>` | 3 | Add a dimension (creates the group if needed) |
| `/dmr group remove <dimension>` | 3 | Detach it with a copy of the current values |
| `/dmr group delete <name>` | 3 | Delete a group; members become independent |
| `/dmr <dimension> <rule> [value]` | 3 | Read/write a rule from the console |
| `/dmr difficulty <dimension> [value]` | 3 | Read/set the dimension's difficulty |
| `/dmr weather <dimension> [clear\|rain\|thunder] [duration]` | 3 | Read/set the dimension's weather |
| `/dmr time <dimension> query` | 3 | Show the time offset and current time of day |
| `/dmr time <dimension> set <day\|noon\|night\|midnight\|0-23999>` | 3 | Move the dimension to a time of day |
| `/dmr time <dimension> add <ticks>` / `reset` | 3 | Shift the offset / return to global time |
| `/dmr recipe <dimension> add\|remove <namespace>` | 3 | Claim or release a recipe namespace |
| `/dmr recipe list <dimension>` / `rebuild` / `check <dimension> <recipe id>` | 3 | Inspect or rebuild the recipe view |
| `/dmr reload` | 3 | Reload the config from disk |

`/dimrule` is a full alias of `/dmr`.

## Groups in 30 seconds

```text
/dmr group create pvp
/dmr group add pvp dimtest:room_a
/dmr group add pvp dimtest:room_b
/dmr group list
/dmr group remove dimtest:room_b
/dmr group delete pvp
```

- Members of a group share **one** rule set: change a rule anywhere in the group and every
  member sees it.
- A dimension belongs to at most one group; adding it elsewhere moves it.
- `remove` copies the group's current values into a private set.
- `delete` dissolves the group; each member keeps the values it had.

## Installation

1. Minecraft **26.3**, Fabric Loader **0.19.5+**, Fabric API, **Java 25**.
2. Drop the jar into the server's `mods/` folder (or your client's for single-player).
3. Clients do **not** need the mod.

**Single-player / LAN:** install it on the machine that opens the world. The integrated server
runs the same server-side code, so rules, groups and commands all work. Enable cheats (or be
op) to use `/gamerule` and `/dmr`.

## Configuration

`config/dimensional-rule-isolation/dimension_rules.json`

```json
{
  "dimensions": {
    "minecraft:overworld": { "keep_inventory": "false" }
  },
  "groups": {
    "pvp": {
      "members": ["dimtest:room_a", "dimtest:room_b"],
      "rules": { "keep_inventory": "true" }
    }
  },
  "difficulty": {
    "minecraft:the_nether": "hard"
  },
  "weather": {
    "dimtest:room_a": { "clear": 0, "rain": 6000, "thunder": 6000, "raining": true, "thundering": false }
  },
  "time": {
    "dimtest:room_a": 7603
  },
  "recipes": {
    "dimtest:room_a": ["room_a"],
    "dimtest:room_b": ["room_b"]
  }
}
```

The file is human-editable; `/dmr reload` re-reads it without a restart.

## Removing the mod

Safe. The mod writes **nothing** into the world save — no registry entries, no `level.dat`
changes; only the JSON above, outside the save folder. Tested by loading a modded world on a
zero-mod Fabric 26.3 server: all dimensions loaded, blocks and player data intact, and rules
fell back to the vanilla global values. See `docs/removal-test.log` in the repository.

## Known limitations

- **Time is an offset, not an independent clock.** Sleeping through the night still moves the
  global clock; the vanilla `/time` command still operates globally. Use `/dmr time` for
  per-dimension time.
- **Recipe isolation covers crafting/furnace/stonecutter/smithing/brewing.** The recipe book
  and `/recipe` still list recipes from every namespace; crafting validation is per dimension.
- **Loot tables, advancements and item/block tags remain global** — those lookups have no
  dimension context to route on.
- Changing a rule makes vanilla broadcast the value to clients (used for client-side
  prediction); server-side values stay per-dimension.
- The vanilla `/difficulty` command still writes the global difficulty; use
  `/dmr difficulty` for a single dimension.
- Do not install alongside another mod that also overrides `ServerLevel.getGameRules()`.

## FAQ

**Does a vanilla client need the mod?** No. It adds no registry content and sends no custom
packets.

**Do datapack dimensions work?** Yes — any dimension registered by a datapack gets its own rule
set automatically.

**Can two dimensions share rules?** Yes, put them in the same group.

**Can two dimensions have different difficulty or weather?** Yes —
`/dmr difficulty <dimension> hard`, `/dmr weather <dimension> rain`. The client HUD follows the
dimension you are in.

**Can one dimension be at night while another is at noon?** Yes, with `/dmr time`; time keeps
flowing and undead burning follows the dimension's displayed time.

**Can two datapacks with conflicting recipes coexist?** Yes, if their recipes use different
namespaces: claim each namespace for its dimension with `/dmr recipe add`.

**Will removing it corrupt my world?** No. The world runs normally; only the per-dimension
differences disappear and all dimensions fall back to the global rules.
