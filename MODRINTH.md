## Summary

Every dimension gets its own `/gamerule` set — including dimensions defined by datapacks.
Group dimensions together to share one rule set, and keep the rest isolated.

## Features

- **Per-dimension gamerules** for the overworld, nether, end and any datapack dimension.
- **Vanilla `/gamerule` just works** — it reads and writes the executing dimension's rules,
  no new syntax to learn.
- **Named groups** — create a group, add dimensions, remove or delete them freely; members
  share one live rule set.
- **Persistent** — rules and groups are stored in a readable JSON file
  (`config/dimensional-rule-isolation/dimension_rules.json`).
- **Server-side only** — no registry content, no custom packets; vanilla clients can join.
- **Cross-dimension death fix** — dying in a `keep_inventory=true` dimension and respawning
  elsewhere no longer deletes your inventory.

## Commands

| Command | Permission | Description |
|---|---|---|
| `/dmr list` | 2 | List groups and ungrouped dimensions |
| `/dmr group create <name>` | 3 | Create an empty group |
| `/dmr group add <name> <dimension>` | 3 | Add a dimension (creates the group if needed) |
| `/dmr group remove <dimension>` | 3 | Detach it with a copy of the current values |
| `/dmr group delete <name>` | 3 | Delete a group; members become independent |
| `/dmr <dimension> <rule> [value]` | 3 | Read/write a rule from the console |
| `/dmr reload` | 3 | Reload rules and groups from disk |

`/dimrule` is a full alias of `/dmr`.

## Requirements

- Minecraft 26.3
- Fabric Loader ≥ 0.19.5 and Fabric API
- Java 25
- Server-side installation (single-player also works)

## Known limitations

- `advance_time` (day/night) is a server-wide clock in 26.3 and is not per-dimension.
- Changing a rule makes vanilla broadcast the new value to clients; server-side values stay
  per-dimension.
